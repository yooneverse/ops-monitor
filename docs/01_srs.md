## 2. 제품 정의

Ops Monitor는 WEB/WAS 운영자가 서비스 상태와 점검 결과를 더 짧은 시간 안에, 더 적은 휴먼 에러로 확인할 수 있도록 돕는 경량 운영 모니터링 도구이다.

이 제품은 단순한 상태 조회용 API가 아니라 아래 운영 질문에 답해야 한다.

- 프로세스는 살아 있는가
- 서비스는 실제로 요청을 받을 준비가 되었는가
- 장애는 새로 발생한 것인가, 이미 지속 중인 것인가
- 지금 어떤 점검 대상을 감시하고 있는가
- 어떤 점검 대상은 예외 규칙으로 제외되어 있는가
- 운영자가 수행한 조치가 무엇이며 결과는 어땠는가

---

## 3. 해결하려는 문제

### 3.1 운영 상의 문제

| 문제 | 설명 |
|---|---|
| 상태 확인 분산 | 프로세스, DB, 부가 서비스, 자원 상태를 여러 곳에서 따로 확인해야 함 |
| 준비 상태 불명확 | 앱이 떠 있어도 실제 서비스 가능 여부를 바로 판단하기 어려움 |
| 이벤트 중복 | 같은 장애가 계속 반복 기록되면 운영자가 실제 전이를 읽기 어려움 |
| 운영 기록 부족 | 점검 1회 단위로 무엇을 확인했고 무엇을 제외했는지 남기기 어려움 |
| 조치 이력 부족 | 운영 액션이 실행되더라도 누가 언제 어떤 결과로 수행했는지 남지 않을 수 있음 |

### 3.2 제품 목표

| 목표 | 설명 |
|---|---|
| 상태 통합 | 생존, 준비, 자원, 부가 서비스, 이벤트를 한 흐름으로 제공 |
| 전이 감지 | 상태값이 아니라 변화 기준으로 incident / recovery 판단 |
| 대상 확장성 | 점검 대상을 레지스트리 형태로 추가 가능하게 설계 |
| 실행 추적성 | 모니터링 루프 1회 단위 리포트 저장 |
| 운영 안전성 | 보호된 API와 설정 검증으로 잘못된 운영 노출을 줄임 |

## 4. 사용자 정의

| 사용자 | 설명 |
|---|---|
| 운영자 | 서비스 상태, 이벤트, 자원 현황을 확인하고 장애 여부를 판단하는 사용자 |

## 5. 기능 요구사항

### 5.1 공개 상태 확인

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| FR-PUB-01 | 루트 상태 확인 | `/`에서 기본 동작 여부를 확인할 수 있어야 한다. | High |
| FR-PUB-02 | 생존 확인 | `/livez`는 프로세스가 떠 있는지만 빠르게 반환해야 한다. | High |
| FR-PUB-03 | 준비 확인 | `/readyz`는 DB 연결 기준으로 준비 상태를 반환해야 한다. | High |

### 5.2 보호된 운영 API

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| FR-OPS-01 | 종합 상태 조회 | `/health`에서 API, DB, 부가 서비스 상태를 확인할 수 있어야 한다. | High |
| FR-OPS-02 | 자원 상태 조회 | `/system`에서 메모리와 디스크 사용량을 확인할 수 있어야 한다. | High |
| FR-OPS-03 | 이벤트 이력 조회 | `/alerts`에서 최근 장애/복구/운영 액션 이력을 확인할 수 있어야 한다. | High |
| FR-OPS-04 | 모니터링 메타데이터 조회 | `/monitoring/status`에서 주기, 임계치, 제외 대상, 경고 정보를 함께 확인할 수 있어야 한다. | High |
| FR-OPS-05 | 운영 대시보드 제공 | `/dashboard`는 운영자가 한 화면에서 주요 상태를 읽을 수 있어야 한다. | High |

이 버전에서 의도적으로 크게 다루지 않는 범위는 아래와 같다.

## 8. 성공 기준

### 8.1 제품 관점

- 운영자가 공개 프로브와 보호 API를 구분해서 사용할 수 있다.
- 장애는 전이 기준으로 감지되고 복구 이력이 남는다.
- 점검 대상을 예외 규칙으로 제외할 수 있다.
- 모니터링 실행 1회 단위 결과를 다시 복기할 수 있다.

### 8.2 포트폴리오/면접 관점

- WEB/WAS 운영 시각으로 설계 이유를 설명할 수 있다.
- 단순 상태판이 아니라 운영 안전성 도구로 설명할 수 있다.
- 기술 선택이 왜 그 구조에 맞는지 문서와 코드에서 함께 보여줄 수 있다.
